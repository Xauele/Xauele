# Xauele

I'm interested in the part of software engineering where "it passed" is only the start of the conversation.

A green pipeline is useful, but I still want to know what it actually proved. Did we test the artifact that was deployed? Did the smoke test exercise a real workflow? If a dependency fails halfway through a request or job, does the system recover cleanly? Can someone else reproduce the result?

That line of thinking keeps pulling me toward release safety, failure handling, reproducibility, observability and system boundaries.

I use AI heavily in development too. It makes the same question more important, not less. An agent can explore a codebase, write code and review changes quickly, but confidence is not evidence. I still want the diff, the failing case, the test and the runtime result.

## Evidence-driven engineering

I'm using that phrase as shorthand for something simple: when we say a change is safe, I want to know what evidence supports the claim and where the gaps still are.

I'm starting to write down notes from that work here.
